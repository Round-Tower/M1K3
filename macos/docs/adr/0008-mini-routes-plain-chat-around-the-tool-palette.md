# 0008. Mini routes plain chat around the tool palette

Date: 2026-09-26
Status: ACCEPTED — Kev, 2026-09-26 (default on; the route speaks in the agent turns' persona)
Deciders: Kev (the ask: "would classification for tools and context ease up the model?") + claude-opus-5-5

## Context

Every Mini (Apple Foundation Models) turn went through the agent loop with the whole tool
palette on offer. A live A/B on 22 chat fixtures with the app quit measured the same turn at a
**51.5 s median with the palette and 13.4 s with none**, and it scored better without (13 → 15).
With tools on offer, Mini consulted one on ordinary chat and then disowned what it knew ("the
capital of Australia" → "not in what I can see"), a second generation synthesised the answer, and
the native tool path never streamed, so the first word arrived at the end.

An empty palette through the AGENT prompt was not the answer: that prompt tells the model to call
tools three times, and with none to call Mini wrote junk (`TOOLS: ["search"]`, the bare date).

## Decision

- **A router decides, per turn, whether the turn needs a tool.** `ToolNeedRouter` is a logistic
  layer over Apple's built-in English sentence embedding (NLEmbedding): nothing downloaded, ~5 ms.
  Its weights are generated by `tools/router/train_tool_router.py` from labelled synthetic prompts;
  the eval fixtures are its test set and never train it. Held out: 42/42 tool asks keep their
  tools, 28/74 no-tool turns go tool-free.
- **It fails open.** Another language, no embedding, a bad vector: the turn keeps the palette.
  Hiding a tool the turn needed is a wrong answer; keeping one it didn't is only slower.
- **A chat verdict gets a route of its own**, not an emptied agent prompt: one streamed
  generation over the turn's context line, history replay and grounding, with tool-free rules
  (`AgentRAGResponder.runPlainTurn`). An empty stream falls back to the agent turn; images always
  take the agent turn.
- **Mini only, on by default.** `ToolRouterWiring` is the one gate both shells read: the flag
  (`miniToolRouter`, absent = on) and the answering brain being Apple's model. Lil gained nothing
  (its time is not tool detours; its prefix cache already absorbs the palette); Big ~18% on chat,
  left as a later call because a per-turn palette churns the MLX prefix cache.
- **The route speaks in the agent turns' persona** (Kev's call): the same voice and follow-up
  chips on either route, for ~0.7 s of first-word time over Mini's trimmed prewarmed persona.

## Consequences

- Mini open chat 51.1 s → 10.1 s; routed turns show their first words in ~5 s. Tool use held
  (10/10), security unchanged. Evidence: `docs/evals/2026-09-26-mini-chat-tools-*.json`,
  `2026-09-26-mini-router-*.json`, `2026-09-26-{lil,big}-router-ab-*.json`.
- A third prompt route for Mini (ReAct floor, native agent, plain chat): a persona or security
  change now owes an eval arm on each. `M1K3_AFM_EVAL_ROUTER` and `M1K3_SELFTEST_CHATEVAL_ROUTER`
  exist for that.
- The router is cautious by design (97% tool recall): most well-known-fact questions still take
  the agent path. More labelled data, or real labels from the router's `.notice` verdict lines,
  is the lever; the threshold is not.
- Tool turns are still ~50 s on Mini: the next latency target, separate from this.
- The spike (Laya, an MLX typed-decision encoder, zero-shot) could not see web asks; trained on
  the same labels, the built-in embedding matched it without a ~1 GB model. Labelled data was the
  lever, not the model.
