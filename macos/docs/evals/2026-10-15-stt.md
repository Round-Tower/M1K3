# Speech to text: accuracy, live latency, name repair (2026-10-15, #611)

Kev's corpus: 30 clips read from `tools/eval/stt_prompts.txt`, en_IE, one speaker, one mic,
about 350 words (`tools/eval/stt_record.sh`). The audio and transcripts stay in
`~/.cache/m1k3-stt-corpus/`; only numbers are recorded here. Held-out set: 22 new sentences
read by the macOS en_IE voice (Moira): 12 with names the corpus never used, 10 traps (ordinary
words that sound like a name in the list).

## 1. File mode: `M1K3_STT_EVAL=1 swift test --filter SpeechToTextEvalTests`

Raw run: `2026-10-15-stt-wer.json`. RTF = processing seconds per audio second.

| arm | WER | everyday | names + jargon | RTF |
|---|---|---|---|---|
| whisper small.en | **8.4%** | 3.2% | 16.8% | 0.096 |
| analyzer, accurate (no `.fastResults`) | 8.9% | **3.2%** | 18.3% | **0.045** |
| dictation + vocabulary | 10.4–11.0% | 6.5% | 16.8% | 0.082 |
| analyzer as shipped (`.fastResults`) | 10.7% | 4.6% | 20.6% | 0.050 |
| analyzer + vocabulary | 10.7% | 4.6% | 20.6% | 0.048 |
| dictation | 11.2% | 6.5% | 19.1% | 0.067 |

- SpeechTranscriber ignores contextual strings: output was byte-identical with and without,
  through the initializer and through `setContext`. DictationTranscriber honours them, but its
  gain sits inside its own run-to-run noise (10.4% and 11.0% on identical runs).
- DictationTranscriber drops the last words of a clip that ends on speech (8/30 clips:
  "at half past [eight]", "what I [said]"). One second of trailing silence fixes it;
  `finalizeAndFinishThroughEndOfInput()` does not. Anything feeding it a live mic must keep
  feeding silence after the speaker stops.

## 2. Live-style streaming (voice mode's options, real time, 100 ms chunks)

Probe: `scratch/stt-latency-2026-10-15` (gitignored). Each clip streams at the audio clock and
is followed by 8 s of silence; finals arrive the way voice-first sees them (never finalized by
hand).

| options | WER | first caption (median / p90) | last final after speech ends (median / p90 / max) |
|---|---|---|---|
| `[.volatileResults, .fastResults]` (shipped) | 10.7% | 1.08 s / 1.94 s | 1.23 s / 1.72 s / 1.86 s |
| `[.volatileResults]` | 8.9% | 3.96 s / 4.02 s | 3.85 s / 4.67 s / 4.74 s |

Accurate mode live costs about 2.6 s per turn and 2.9 s to the first caption: not shippable
as is. One accurate file pass over a finished utterance (about 4 s, plus 1 s of silence) costs
0.18 s including analyzer setup (Whisper: 0.40 s). So a second, accurate pass over the
buffered utterance at the endpoint buys the accuracy for about 0.2 s.

## 3. Name repair (`NameRepair` in M1K3Voice; spike: `scratch/name-repair-2026-10-15`, gitignored)

Swap a 1–3 word span for a known name when they sound alike: a sound key (digits spoken, Irish
digraphs bh/mh to v, dh/gh silent, vowel clusters and doubled letters collapsed), Levenshtein
similarity ≥ 0.75. "Karen 2 Hill" and "Carrauntoohil" fold to the same key. Guards: the span
needs a capital that doesn't just open a sentence (or ≥ 2 words at ≥ 0.92), may not begin or
end on a function word; known names, weekdays and months are locked; and the best name must
sound at least 0.10 closer than the next, or the span is left alone (an ambiguous span claims
its words, so a shorter span inside can't slip a name in). Names: the 19 the corpus uses plus
70 other Irish names and places, so most of the list is distractors. Numbers are the Swift type
at its defaults (it matches the Python spike on 310 of 312 transcripts; the two it differs on,
the spike ate a real word).

| | names before → after | everyday / traps | overall |
|---|---|---|---|
| Kev, analyzer as shipped (guards tuned here) | 20.6% → 9.9% | 4.6% → 4.6% | 10.7% → **6.6%** |
| Kev, analyzer accurate | 18.3% → 7.6% | 3.2% → 3.2% | 8.9% → **4.9%** |
| Kev, whisper | 16.8% → 8.4% | 3.2% → 3.2% | 8.4% → 5.2% |
| held-out, analyzer as shipped | 25.2% → 15.0% | 1.2% → 1.2% | 14.8% → 9.0% |
| held-out, analyzer accurate | 23.4% → 14.0% | 0 → 0 | 13.2% → 7.9% |
| held-out, whisper | 26.2% → 9.3% | 0 → 0 | 14.8% → 5.3% |

No trap was altered on any arm ("school"/Schull, "calm"/Colm, "abandon"/Bandon,
"launch"/Lahinch, "marshmallow"/Mallow, "inch"/Inch). The margin trades names for safety
(swaps that put in a name the reader said vs one they didn't, both sets, all six arms):

| margin | right | wrong |
|---|---|---|
| 0 | 103 | 11 |
| 0.05 | 101 | 5 |
| **0.10 (default)** | 92 | 3 |
| 0.15 | 88 | 2 |

Every swapped word was already wrong, so a wrong swap doesn't move WER; it matters because a
wrong name reads as right and the distiller would keep it. The three left are one held-out
sentence every engine garbled ("Sercha ... Cathurst, Irene" for "Saoirse ... Cahersiveen").

Speed: 5.8 ms per 33-word turn against 2,000 names (names whose length alone rules them out
are skipped, which is exact for both the winner and the runner-up). The pre-push review's fold
(leading punctuation, possessives, duplicate names, verbatim untouched text, a short single word
needing ≥ 0.8) left every number above unchanged; the 0.8 short-word bar was set knowing it
keeps one held-out repair ("Gron" → Gráinne), so that set is no longer fully unseen.

Repairs it makes: Karen 2 Hill → Carrauntoohil, Don Leary → Dún Laoghaire, Clinic Hill →
Clonakilty, Gubenbarra → Gougane Barra, Bally Bunion → Ballybunion, Swift UI → SwiftUI,
phosphor fox → PhosphorFox, Macrome → Macroom, Berlin College → Ballincollig, Castle Tamber →
Castletownbere.

`challenger` (2026-10-15): the memory graph has no entity table (`MemoryStore` holds free-text
facts), so "names from the graph" would mean scraping capitalised words, garbles like "Karen
Tugel" included, and repair would then lock the garble in. Its build order: NameRepair first
at the `TranscriptSanitizer` seam (voice-first and dictation, never typed chat) with a curated
list, repaired spans kept out of distillation, a `.notice` breadcrumb per repair and an argv
kill switch; the polish pass (accurate re-run at the endpoint) deferred until it beats fast by
≥ 2 points on a second real speaker.

**Wired 2026-10-16** (Kev: "let's wire what we've built, no point losing it"). `VoiceTurnPreparer`
runs NameRepair on every voice-first turn, Mac and iOS, never on typed chat or dictation. There
is still no curated list, so the names are `KnownNames`: the user's display name plus capitalised
runs in memory facts, learned at voice-mode entry. That is challenger's warned case: a garble
already in memory becomes a target. A repair only swaps toward a name already in memory, so it
can't add a new one. Every swap logs a `.notice` (`stt`, words private), and `-voiceNameRepair
NO` at launch turns it off.

## Caveats

One speaker, one session, one mic: half a point is one or two words. The held-out set is a
synthetic voice, whose mishearings differ from a person's. No threshold is set from this.

Owed: a second corpus session (noisy room, AirPods), ideally a second speaker, before any call
on Whisper, the polish pass or NameRepair's thresholds.
